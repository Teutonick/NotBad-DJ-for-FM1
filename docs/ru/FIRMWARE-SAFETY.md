# Безопасность прошивки FM‑1

[English](../FIRMWARE-SAFETY.md)

В **Настройки → Прошивка** доступна диагностика без записи. Для релиза 0.1.0 [манифест](../../src/fm1/updater/releases.json) фиксирует SHA‑256 пакета, его идентификатор и закреплённые версии fm1-base и felucca-bsp. JEDEC ID `856014` (Puya P25Q80H) и `B36014` (UCUN UC25HQ80) внесены как известные чипы. По данным владельца физические проверки 0.1.0 проходили только на Puya P25Q80H с JEDEC ID `856014` и m-bootloader 2.3. Другие сочетания не проверены и могут привести к проблемам с устройством. Версия штатной прошивки, ответ OTA и название MIDI-порта сами по себе не определяют чип и установленный загрузчик. [Проверка JEDEC в исходниках fm1-base](https://github.com/charlesvestal/fm1-base/blob/b0c384b21b095fb4f940025ce6ce7348625b4dda/device/fm1_flash_ok.h)

## Диагностика и резервная копия

1. Полностью зарядите FM‑1, подключите его напрямую исправным USB-кабелем передачи данных, отключите сон компьютера и закройте другие MIDI-приложения. Оставьте подключённым только один контроллер.
2. Запустите [M-Flasher](https://github.com/jvitkauskas/m-flasher) в режиме диагностики и сохраните доступные сведения об устройстве из Device Info. Запишите JEDEC ID, размер Flash, текущую прошивку и загрузчик. Если сведения недоступны, оставьте их неизвестными. Вкладка прошивки распознаёт введённый JEDEC ID, а опрос MIDI показывает идентификатор, который сообщает устройство, и JEDEC ID, если прошивка передала его в расширенном ответе. [Формат ответа в BSP](https://github.com/hugelton/felucca-bsp/blob/7b77bfbce8e0d185461a79d164c893551492ded1/chip/ota.c#L153-L181)
3. Выполните два независимых полных чтения Flash с одного устройства, по 1 МиБ каждое. Сохраните оба файла в отдельной папке и выберите их во вкладке прошивки. Она сравнит содержимое побайтно и покажет SHA‑256 совпавших файлов. Сохраните хеш рядом с дампами и аппаратным отчётом. Совпадение файлов подтверждает их содержимое. Происхождение файлов и независимость чтений требуют подтверждения средствами диагностики.
4. Загрузите соответствующий штатный пакет с [M‑VAVE](https://www.m-vave.com/download) и сохраните его вместе с информацией об исходной версии. У V15 и V16 различается карта Flash. Уточните версию до выбора процедуры. [Руководство FM1 Unbricker](https://quixotic7.github.io/MvaveFM1Unbricker/)
5. Выберите пакет 0.1.0 из [релиза](https://github.com/Teutonick/NotBad-DJ-for-FM1/releases/tag/v0.1.0). Приложение сверяет идентификатор, SHA‑256, структуру и внутренние контрольные суммы UFW. [Формат FWSC](https://sbegueria.github.io/fm1-dev-wiki/Firmware-Package-Format.html)

## Восстановление

- Устройство загружается штатно. Сохраните текущий дамп и подтвердите доступность подходящего инструмента восстановления.
- Появляется только MIDI-порт OTA. Сохраните питание, определите идентификатор загрузчика и используйте руководство для этой версии. Возобновление записи возможно только с совместимым пакетом для данного загрузчика. [Протокол OTA](https://sbegueria.github.io/fm1-dev-wiki/Update-Protocol-and-Installers.html)
- Устройство отображается как `WL82 UBOOT1.00`. Следуйте инструкции для ROM и этой ревизии чипа. Для полного восстановления используйте проверенный дамп этого экземпляра и инструмент с поддержкой его JEDEC ID и проверкой записанных данных. [FM1 Unbricker](https://quixotic7.github.io/MvaveFM1Unbricker/)
- Устройства по USB нет. Проверьте питание и прямое подключение. Если USB по-прежнему отсутствует, используйте ветку руководства для входа в ROM. [FM1 Unbricker](https://quixotic7.github.io/MvaveFM1Unbricker/)

Через USB MIDI можно узнать идентификатор прошивки и обслужить запросы OTA на чтение пакета. Закреплённый OTA-загрузчик читает записанные сектора обратно и сравнивает байты на устройстве. Для независимой сверки Flash на компьютере и восстановления полного дампа нужен отдельный транспорт. [Проверка секторов в BSP](https://github.com/hugelton/felucca-bsp/blob/7b77bfbce8e0d185461a79d164c893551492ded1/loader/ldr_core.c#L182-L197) При обрыве питания USB MIDI может исчезнуть, а ROM может потребовать ручного входа. Приложение не запускает повторную запись или откат по тайм-ауту. [Протокол OTA](https://sbegueria.github.io/fm1-dev-wiki/Update-Protocol-and-Installers.html)

## Условия допуска к записи и автооткату

Для каждого допуска укажите JEDEC ID, исходную прошивку, загрузчик, карту Flash, SHA‑256 пакета, версии инструментов и результаты проверки на физическом FM‑1. Нужен способ подтвердить эти данные и принадлежность бэкапа именно подключённому экземпляру. Проверку восстановления следует проводить на тестовом устройстве с подготовленным входом в ROM.

Зафиксируйте результаты прерывания при подготовке OTA, появлении загрузчика, стирании, записи, проверке и перезапуске. Сверьте данные, прочитанные из Flash после записи, с ожидаемыми диапазонами образа. После перезапуска отдельно проверьте дисплей, органы управления, USB MIDI, USB Audio и доступность повторного обновления без запуска записи. Автоматический откат можно разрешить только там, где средство восстановления подтвердило идентичность устройства, свой доступ к записи и вариант карты Flash. Для остальных состояний используйте помощник восстановления.


Для каждого нового выпуска применяется [Firmware Safety Gate](FIRMWARE-SAFETY-GATE.md).
